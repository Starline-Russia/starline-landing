# Starline Landing v3 Skill — дизайн

## Цель

Создать отдельный персональный skill `starline-landing-v3`, который воспроизводит согласованный процесс разработки лендинга Starline v3 на Astro: от запуска чистого starter-проекта до изолированной правки секций и локальной проверки. Существующий `starline-landing`, а также проекты `v1` и `v2`, не изменяются.

Skill устанавливается в `/Users/papenov/.codex/skills/starline-landing-v3` и содержит стабильный снимок текущего `v3`. Изменения рабочего проекта после установки не синхронизируются автоматически: обновление снимка выполняется только по отдельному запросу.

## Структура skill

starline-landing-v3/

## Ответственность файлов

### `SKILL.md`

Кратко задаёт обязательный рабочий процесс:

1. Создать новый проект из bundled starter, не редактируя starter внутри skill.
2. Работать с одной секцией за раз через `/preview/<section>/`.
3. Сначала обновлять структурный контракт, затем компонент и стили.
4. Проверять `npm test`, `npm run check`, `npm run build` и нужный preview в браузере.
5. Сохранять доступность без JavaScript, адаптивность и reduced-motion fallback.

Описание skill начинается с `Use when…` и содержит только условия срабатывания: создание, продолжение, редизайн или проверка Astro-лендинга Starline v3 и его отдельных секций.

### `references/v3-contract.md`

Хранит подробности, которые не должны раздувать основной skill:

- технологический стек Astro 7.0.9, strict TypeScript и обычный CSS;
- визуальные токены: ночной фон, `#3F09B1`, `#C57DFB`, `#171027`, `#F7F6F9`, белый; lime исключён;
- типографику Onest/Inter;
- порядок секций и их обязательные ID;
- утверждённые факты, тексты, ограничения и оговорку для `+20–50% GMV`;
- правила компонентных preview-маршрутов;
- accessibility, responsive и browser-QA контракт;
- запрет на вымышленные имена клиентов, команды, гарантии и неподтверждённые показатели.

### `assets/starter/`

Самодостаточная копия текущего `v3`: компоненты, страницы, стили, ассеты кейсов, логотип и preview-маршруты. Тесты переносятся внутрь starter, а npm-скрипты используют локальный `tests/`, чтобы проект не зависел от структуры исходного репозитория.

### `scripts/create-v3.sh`

Принимает один целевой путь, создаёт его при необходимости и копирует туда starter. Скрипт прекращает работу, если целевая папка непустая, поэтому не перезаписывает существующий проект. После копирования зависимости устанавливаются пользователем обычной командой `npm install`.

## Компонентный цикл

Каждая крупная секция остаётся отдельным Astro-компонентом. Полная страница собирает те же компоненты, а `/preview/hero/`, `/preview/tasks/`, `/preview/cohorts/` и последующие preview-страницы показывают по одному компоненту в корректном layout-контексте.

Изменение секции считается завершённым, когда:

- preview отображает только нужный компонент;
- полная страница не расходится с preview;
- структурные тесты отражают согласованный контент;
- отсутствуют ошибки Astro/TypeScript и production build;
- проверены desktop и mobile, focus-состояния и overflow.

## Обработка ошибок

- Непустой target для `create-v3.sh` — понятная ошибка без частичного копирования.
- Отсутствующий starter — явная ошибка с ненулевым кодом завершения.
- Недоступные зависимости — skill сообщает о необходимости выполнить `npm install`, но не подменяет версии пакетов.
- Несовпадение снимка и рабочего проекта не исправляется автоматически; синхронизация выполняется отдельной операцией.

## Проверка

Перед установкой:

1. Запустить `quick_validate.py` для структуры skill.
2. Проверить создание проекта в новой временной папке и отказ для непустой папки.
3. Убедиться, что starter не содержит запрещённых локальных директорий.
4. В скопированном starter выполнить `npm test`, `npm run check` и `npm run build` с локально доступными зависимостями.
5. Проверить наличие preview-маршрутов и обязательных ассетов.

После этого скопировать проверенный skill в `/Users/papenov/.codex/skills/starline-landing-v3` и повторно выполнить структурную валидацию по установленному пути.
